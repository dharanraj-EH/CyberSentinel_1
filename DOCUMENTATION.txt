CyberSentinel - Comprehensive Project Documentation
=================================================

Version: 0.1.0
Platform: Windows-first (works cross-platform with Python 3.9+)

Overview
--------
CyberSentinel is a desktop vulnerability scanner with a modern PyQt5 GUI. It integrates:
- Network scanning (Nmap and a pure Python socket fallback)
- SSL/TLS analysis (certificates, protocols, ciphers, and vulnerability checks)
- Web tests (security headers, SQLi, XSS, CSRF)
- Reporting (JSON, HTML, PDF) stored under the user profile for later review

Primary Entry Points
--------------------
- GUI: cybersentinel/cybersentinel/gui_main.py
  • Function: main()
  • Class: CyberSentinelApp (QApplication wrapper)
  • Creates and shows MainWindow, applies styles, sets app icon, splash

- CLI Tool (batch web audit): cybersentinel/cybersentinel/tools/web_audit_runner.py
  • Module Main: python -m cybersentinel.tools.web_audit_runner --urls <url1> <url2> ...
  • Runs 4 checks (headers, SQLi, XSS, CSRF) and generates JSON/HTML/PDF reports

Runtime Data & Report Storage
-----------------------------
- All generated outputs are stored under the user home directory:
  Windows: %USERPROFILE%\.cybersentinel\reports\
  Linux/macOS: ~/.cybersentinel/reports/
- The application’s Dashboard and Reports tab both consume this directory structure.

GUI Modules
-----------
1) Main Window: cybersentinel/cybersentinel/gui/main_window.py
   - Class: MainWindow(QMainWindow)
   - Responsibilities:
     • Creates the main tab widget and adds 5 tabs: Dashboard, Network Scanner, SSL/TLS Analyzer, Web Tests, Reports
     • Sets up Menus (File/Edit/View/Help) and a main Toolbar
     • Hooks actions like New Scan, Open, Save, Generate Report (stubs), About dialogs
     • Exposes references: self.dashboard_tab, self.scanner_tab, self.ssl_tab, self.web_tests_tab, self.reports_tab

2) Dashboard: cybersentinel/cybersentinel/gui/dashboard.py
   - Class: DashboardTab(QWidget)
   - Sections:
     • Welcome banner with app version and icons
     • Quick Actions buttons: New Scan, SSL Analyzer, Web Tests, Reports (navigate to corresponding tabs)
     • Recent Scans: auto-loads latest 10 entries from %USERPROFILE%\.cybersentinel\reports\network and web_audit
       - Items include: target, date, status, findings
       - View button: opens report.html, else report.pdf, else report.json; fallback opens run folder
       - Refresh button: manual reload; also auto-refreshes after Network scan completes
     • Status section (placeholder)

3) Network Scanner Tab: cybersentinel/cybersentinel/gui/scanner_tab.py
   - Core Features:
     • Target selection and Start/Stop controls
     • Scanner type: Nmap (recommended) or Built-in Socket Scanner
     • Ports input plus Presets: Custom, Well-known (0-1023), Registered (1024-49151), Dynamic/Ephemeral (49152-65535), All (1-65535)
     • Scan type presets, Timing templates (T0..T5), flags for service detection, OS detection, aggressive, NSE script scan
     • Live Nmap output streaming into the “Nmap Output” tab
     • Parsed outputs into UI tabs:
       - Ports/Hosts table (Port, Protocol, State, Service, Version)
       - Topology (Traceroute hops)
       - Host Details (status, addresses, hostnames, uptime, sequences, times)
       - Scans (shows the exact Nmap command executed)
     • On completion, results are persisted to user reports and PDF/HTML/JSON are generated
       - Transcript (nmap_output.txt) is also saved
       - Dashboard recent list is auto-refreshed

   - Class: ScanWorker(QThread)
     • Builds Nmap arguments from UI options
     • Uses NmapScanner (streamed output) or SocketScanner
     • Emits progress, completion, error, and output_line signals

4) SSL/TLS Analyzer Tab: cybersentinel/cybersentinel/gui/ssl_analyzer_tab.py
   - Core Features:
     • Target + Port controls, protocol selection (SSLv2/3; TLS 1.0/1.1/1.2/1.3)
     • Options: Check certificate validity, cipher suites, and known vulnerabilities
     • Certificate Tab shows:
       - Subject, Issuer, Valid From/To, Days Left (color-coded), Serial Number
       - Signature Algorithm, Public Key Type and Key Size
       - TLS Version and negotiated Cipher (name, bits)
       - Subject Alt Names (SANs), Verified (Yes/No), Hostname Match (Yes/No)
     • Protocols & Ciphers Tab: lists protocols supported and cipher names
       - Insecure protocols highlighted (SSLv2, SSLv3, TLS 1.0/1.1)
     • Vulnerabilities Tab: table with Severity, Name, Description, Remediation

   - Backend: SSLScanner in scanner/ssl_tests.py
     • Uses the ‘cryptography’ package to parse certificates (DER) and extract details accurately
     • Checks for: expired/expiring certificates, self-signed/unverified, weak protocols, weak/vulnerable ciphers,
       weak signature/hash (MD5/SHA1), weak RSA/EC key sizes, missing SAN, hostname mismatch
     • Negotiates TLS and collects supported ciphers per protocol (best-effort; python/OpenSSL dependent)

5) Web Tests Tab: cybersentinel/cybersentinel/gui/web_tests_tab.py
   - Runs selected tests in a background thread via WebSecurityTester (alias of WebVulnerabilityScanner)
   - Tests available: headers, cors, clickjacking, csrf, xss, hsts, csp, cookies, http_methods, directory_listing, server_info
   - Displays progress, results with colored severity, per-test details, and a textual output window
   - Save JSON results

6) Reports Tab: cybersentinel/cybersentinel/gui/reports.py
   - Browses reports under %USERPROFILE%\.cybersentinel\reports\
   - Tree View shows categories (network, web_audit), runs, and report files (JSON/HTML/PDF)
   - Double-click to open a file; buttons to Refresh, Open Reports Folder, and Delete Selected

Scanning Backends
-----------------
1) Nmap Wrapper: cybersentinel/cybersentinel/scanner/nmap_wrapper.py
   - Class: NmapScanner
   - Verifies ‘nmap’ presence; runs with arguments; supports streaming stdout to UI callback
   - Optional XML output parsing:
     • Hosts -> Ports with detailed state/service fields, OS matches, hostnames, addresses, traceroute hops, run stats

2) Socket Scanner: cybersentinel/cybersentinel/scanner/socket_scanner.py
   - Class: SocketScanner
   - Pure Python TCP scan with concurrency; UDP (best-effort)
   - Resolves target, parses port ranges/lists, returns open/closed with guessed service names

3) SSL/TLS Scanner: cybersentinel/cybersentinel/scanner/ssl_tests.py
   - Class: SSLScanner; Result container: SSLScanResult
   - Uses Python ‘ssl’ with robust protocol mapping; gracefully skips SSLv2/3 when unsupported
   - Certificate parsing via cryptography.x509 on DER-form:
     • Subject, Issuer, Serial, NotBefore/NotAfter, Signature Hash, Public Key type/size, SANs, Self-signed, Hostname match
     • Negotiated TLS version and cipher for the peer connection
   - Vulnerability checks add findings with severity and remediation hints

Reporting
---------
1) JSON: cybersentinel/cybersentinel/reporting/json_report.py
   - JSONReportGenerator.generate(scan_data, output_path) writes enriched JSON with timestamp and summary
   - Includes severity counts and a metadata block (_metadata)

2) HTML: cybersentinel/cybersentinel/reporting/html_report.py
   - HTMLReportGenerator uses Jinja2 templates in reporting/templates (and static assets)
   - Generates index.html and copies assets; embeds charts-ready data
   - If templates are missing, HTML generation may be skipped (handled in callers)

3) PDF: cybersentinel/cybersentinel/reporting/pdf_report.py
   - PDFReportGenerator uses ReportLab; styles defined in DEFAULT_STYLES
   - Sections: Cover page, Table of Contents, Executive Summary, Detailed Findings, Scan Details, Appendix (Glossary, Disclaimer)
   - Severity colors: Critical, High, Medium, Low, Info

Web Testing Engine
------------------
- Module: cybersentinel/cybersentinel/web_tests/sql_xss_csrf.py
  • Class: WebVulnerabilityScanner (aliased as WebSecurityTester)
  • scan(url) collects page headers, cookies, forms, basic exposures (robots, sitemap, .git/HEAD)
  • test_sql_injection(): tries payloads in query and forms, checks for error signatures
  • test_xss(): reflected/stored XSS patterns; simple reflection and encoding checks
  • test_csrf(): presence of tokens, SameSite cookies, Origin/Referer validation
  • Returns structured findings with severity, evidence, and recommendations

Tools
-----
- cybersentinel/cybersentinel/tools/web_audit_runner.py
  • Batch runner for multiple URLs
  • Builds ‘findings’ from scanner results + security headers
  • Generates JSON, HTML (if templates available), and PDF reports under web_audit/

Utilities
---------
- cybersentinel/cybersentinel/utils/resource_loader.py
  • get_resource_path(): resolves bundled resources; works with/without PyInstaller
  • load_icon(), load_stylesheet(), load_ui() helpers with logging on missing resources

How to Run
----------
1) Install Python 3.9+ and Nmap
2) Create and activate virtual environment
3) Install dependencies from cybersentinel/requirements.txt
4) Start the GUI:
   python -m cybersentinel.cybersentinel.gui_main

Where Reports Are Saved
-----------------------
%USERPROFILE%\.cybersentinel\reports\
  network\<target>_<timestamp>\
    - report.json, report.html (optional), report.pdf, nmap_output.txt
  web_audit\<host>_<timestamp>\
    - report.json, report.html (optional), report.pdf

Notable Dependencies (Pins in cybersentinel/requirements.txt)
------------------------------------------------------------
- PyQt5==5.15.9 (GUI)
- reportlab==4.1.0 (PDF)
- cryptography==41.0.0 (SSL certificate parsing)
- python-nmap==0.7.1 (nmap XML support if needed)
- beautifulsoup4==4.12.2, lxml==4.9.3 (HTML parsing)
- Jinja2==3.1.4 (HTML reports)

Troubleshooting
---------------
- ModuleNotFoundError: cryptography -> pip install cryptography==41.0.0
- PDF issues -> pip install reportlab==4.1.0
- HTML report warnings -> ensure Jinja2 is installed and templates are present
- Nmap not found -> install Nmap and ensure it is in PATH

Security & Legal Notice
-----------------------
This tool is for authorized security testing and educational use. Do not scan systems without explicit permission. Findings are best-effort and may include false positives/negatives. Always validate with manual testing.
